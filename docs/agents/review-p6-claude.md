## Findings (most severe first)
1. MEDIUM server/app/main.py:150-152 — POST /api/tts is unauthenticated and takes arbitrary text (<=2000 chars) + voice_id. Once ELEVENLABS_API_KEY is set, anyone reaching the tunnel can burn ElevenLabs credit and grow server/cache/tts without bound (up to 10 MB per unique text, tts.py:47). Breaks: secrets/paid-service hygiene. Fix: accept {room, kind} and render only the room's current intro/counteroffer/verdict text server-side, or require the screen's room + rate-limit; cap cache size.
2. LOW-MED apps/web/src/screen/Sparks.tsx:21-35 — rAF loop runs forever at 60 fps from mount, doing 2x getBoundingClientRect (forced layout) + clearRect every frame even with zero particles. Not a cross-round leak (single mount, cancelled on unmount), but constant projector CPU/GPU at 1080p. Fix: stop scheduling when particles is empty; restart in spawn().
3. LOW-MED apps/web/src/screen/IntroMedia.tsx:12-18 — Matterport iframe only mounts when its beat starts (~6.25 s into an 8 s INTRO) and gets a 1000 ms onLoad deadline; on venue Wi-Fi the showcase will almost always miss it, so every round removes the iframe and toasts "Interior tour unavailable". Fix: preload hidden during the dive, and treat slowness as a silent caption fallback (toast only on real error). Sandbox itself is fine: sandbox="allow-scripts allow-same-origin allow-pointer-lock", no `allow` (no mic/camera), referrerPolicy no-referrer, URL built from an 11-char alnum model_id (effects.ts:22-23), not a dossier URL.
4. LOW server/app/main.py:155-167 — pitch_audio size limit is checked after Starlette has already spooled the whole multipart file (Starlette 1.10 max_part_size only bounds non-file fields), so a multi-GB upload lands on disk before the 413. Content-type check (line 170) trusts the client header (bytes only forwarded to ElevenLabs, never stored, so acceptable). Fix: reject on Content-Length > ~5.5 MB before parsing (middleware or Request header check).
5. LOW server/app/main.py:162 — "auth by player" is player_id possession only; ids are 8 hex chars and are broadcast to all clients in room_state, so any participant can voice-pitch as another player. Same trust model as the pre-existing WS rebind (main.py:222), so not a regression; flag for Phase 8 if impersonation matters.
6. LOW apps/web/src/screen/music.ts:16 — +3 dB lift stacks without bound per repeat category (5 housing revivals = -12 dB vs -24 base); restore() (line 70-73) drops the lift on reconnect. PRD says "+3 dB lift instead of a duplicate"; suggest cap at one lift (or +6 max).
7. LOW apps/web/src/screen/overlays/ConceptCard.tsx:23 — "Before · Dark office" asserts status; the revived building may be partial/occupied per dossier. Not 'vacant' (good) but a soft unsourced claim. Fix: "Before" alone, or use the dossier's floor status label.
8. LOW apps/web/src/play/recorder.ts:68-82 + recorder.ts:99 — with no SpeechRecognition and no ElevenLabs key (current reality on iOS w/o webkit recognition / Firefox), the phone records, uploads, gets 503, then tells the user "Try browser dictation" that does not exist. Typed input still works. Fix: expose an stt_available flag (e.g. /api/health) and hide hold-to-talk when neither path exists.
9. INFO apps/web/src/screen/music.ts:171-172 vs server/app/voice/tts.py:35-52 — "streaming" TTS buffers the full mp3 server-side before returning a URL; client aborts /api/tts at 5 s, so long verdict lines will fall back to browser speech while the server still finishes caching. Functional, but not true streaming. stt.py:23 uses model_id 'scribe_v2' — unverified without a key.
10. INFO apps/web/src/screen/media.ts:5 — import.meta.glob over /public/media is evaluated at dev-server start/build; media dropped in later needs a restart. Fonts are local("...") only (screen.css:1-2), no files in public/fonts — falls back to system fonts unless installed on the projector laptop.
