## Findings (highest severity first)

1. **P1 — Fiction marking still bypasses factual grounding.** `server/app/agent/persona.py:184` and `:240` implement a finite vocabulary denylist, then `:243` accepts everything else; `:490` preserves the accepted sentence as `fact_ref:null, fiction:true`. Reproduced independently against the real hero dossier: adding **"I have a gym.", "I survived a fire.", "I am wheelchair accessible.", "I contain asbestos.", or "My interior is fireproof."** to the persona passes both `validate_persona` and `normalize_writer_persona`, survives unchanged, and produces an empty dropped-lines list. These are physical/history/safety claims without source facts, not fictional emotions. This regresses the earlier closed vocabulary boundary and violates AGENTS #3/#4, PRD Characters, and fix2 item 1. **Fix:** distinguish emotional/metaphorical speech from affirmative property/history assertions and require a checked source citation for the latter; use conservative deterministic acceptance for ambiguous assertion shapes, preserving the new in-character flourishes; add all five negative regressions plus positive character cases. Expanding the noun blacklist alone does not close this class of hole. The currently committed persona does not contain these bad claims.

2. **P2 — Height hard limits fire on width/length.** `server/app/agent/persona.py:347` collects every feet measurement as height, and `:364` compares all of them to `buildingHeightInFeet`; `server/app/agent/fake_agent.py:80` uses the result in live offline play. Reproduced: **"A mural 300 ft wide"** and **"A 400 ft long indoor running track"** both produce **"I stand 297 feet tall; anything taller is a different building, darling."** Neither pitch requests height above the building's height. This violates fix2 item 2 and the dispatched requirement that numeric constraints fire only when the corresponding bound is exceeded. **Fix:** bind quantities to the requested dimension; ignore explicit horizontal measurements and ambiguous unrelated feet quantities; add width/length/height counterexamples through `challenge`.

3. **P3 — Strict threshold boundaries have no regression coverage.** `server/tests/test_prep_agent.py:650` covers smaller quantities, but not equality. Replacing every `> cap` in `limit_applies` (`server/app/agent/persona.py:359`, `:361`, `:363`, `:365`) with `>= cap` still yields **251 passed, 1 skipped for the entire Python suite**. The current implementation itself correctly accepts equality, verified independently for every derived limit including each named dark floor. **Fix:** parameterize below/equal/above assertions for typical-floor area, named-floor area, total dark area, stories, height and parking, including `fake_agent.challenge`; ensure the >= mutation fails.

4. **P3 — Two prep failures still provide no toast event (inherited finding).** `server/app/main.py:113` and `:115` return HTTP 422/503 without the error broadcast used at `:109`. Offline direct endpoint probes with valid host authorization and mocked `ValueError` / `RuntimeError` returned 422 / 503 with **zero room events**. This is the error-UX gap already noted in review-p4-codex and conflicts with AGENTS #9. **Fix:** broadcast a safe error event for both exception branches and test the websocket event without leaking exception text.

5. **P3 — Inner scout tool events still lose their owner (inherited finding).** `server/app/agent/prep_agent.py:56` labels all tool calls `research`; `:57` only resolves a stage when the tool itself is `task`. Consequently scout-internal kit/Vexcel calls still lack `property_scout` / `spatial_scout` attribution, as reported in review-p4-claude finding 5. The prior synchronous websocket wait is fixed at `server/app/main.py:106`. **Fix:** track parent-run ownership or callback metadata and assert the owner of actual inner tool events, not only the delegation task events.

6. **P3 — HTTP prep still does not rebuild floors (inherited finding).** The route at `server/app/main.py:108` calls `prep_building`, which publishes persona/dossier at `server/app/agent/prep_agent.py:242` without a floor-artifact rebuild; that step exists only in `scripts/prep_building.py:37`. This remains review-p4-claude finding 6 and the PRD prep-mode discrepancy. Current committed floor artifacts are valid and byte-for-byte match the deterministic rebuild, so this does not affect today's round. **Fix:** share a deterministic finalization step or explicitly reconcile the HTTP contract with the intended behavior.

7. **P3 — The browser suite is not repeat-isolated (pre-existing).** `apps/web/e2e/data-mode.spec.ts:22` always begins by switching to fixtures and `:29` insists on seven new dossier fetches, while `apps/web/e2e/phase4.spec.ts:8` ends its last iteration in fixtures mode. With `--repeat-each=2`, iteration two's same-mode click performs no data-mode transition and receives zero dossier refreshes: **37 passed / 1 failed**, expected 7, received 0. Both specs predate this diff; this is a test-setup issue rather than evidence of a Phase 4 product regression. **Fix:** establish a known opposite mode before measuring or choose the opposite of the current mode, then restore it. Fresh-process runs are reported separately below.
