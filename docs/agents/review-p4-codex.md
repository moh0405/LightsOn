1. **P1 — The model can write the trusted dossier cache, bypassing deterministic validation on the next request.** `server/app/agent/prep_agent.py:109` roots the model's writable FilesystemBackend at the same directory used for trusted `dossier.json` (`:141`, `:184`). The comment at `:182` claiming the backend cannot write there is incorrect for `result_path`. **Reproduced offline:** a fake failed graph used the actual FilesystemBackend to write `/dossier.json` with stories and the corresponding fact changed from the source's 27 to 999, then raised SpendUnavailable; the first prep returned unavailable, while the next ordinary prep returned ready with 999 stories. This breaks AGENTS #3/#4 and the intended model-output trust boundary. **Fix:** put writable research files in a separate scratch directory inaccessible to the accepted-artifact backend; publish accepted cache outside that root only after validation. Validate cache schema/status and a source/version fingerprint against the current provider, retaining trusted source facts/floors rather than trusting cache-supplied replacements. Add the failed-run/cache-poisoning regression using the fake model/backend.

2. **P1 — Generated hard_limits are descriptions, not physical constraints that can reject a pitch.** `server/app/agent/persona.py:91-94` accepts any verified fact sentence, including names, address, dates and classification; empty lists also pass. `prep_agent.py:96-97` explicitly instructs the writer to copy those sentences. The committed hero's nine limits (`server/fixtures/personas/233953.json:9-18`) include “My name is Esperson,” its address, completion/renovation dates and Office/Class B labels. None specifies a pitch rejection condition. This fails PRD Characters / Persona generation rules and the task's explicit hard-limit requirement. **Reproduced:** the validator accepts a persona whose only hard limit is the building-name sentence. **Fix:** generate a deterministic allowlist of game constraint templates from non-null, verified physical quantities, especially the offered floors' actual area and availability; validate each against its source fact and reject identity/history/classification entries. For example, a single-floor proposal on floor 6 must fit its recorded 31,503 sq ft; this is an area constraint, not an assertion about engineering or legal feasibility. Allow unknown constraints to remain absent, with an explicit validation diagnostic instead of substituting biography. Do not infer roof loads, permits, floor depth, zoning or structural capacity.

3. **P2 — Spend accounting can meter a different model/output bound than the request actually sent.** `server/app/agent/spend.py:114-117` prices `self.model_id` and only top-level max_tokens/maxTokens, then forwards all kwargs to ChatBedrockConverse. The installed Converse implementation also accepts `model_id` and nested `inference_config` request overrides. **Reproduced with a fake client and a temporary ledger:** a Sonnet wrapper with max_tokens=1, cap=$0.05 and invoke(inference_config={'max_tokens':4096}) sent maxTokens=4096 and completed with ledger total **$0.067617**, exceeding its cap. invoke(model_id='us.anthropic.claude-opus-4-6') sent Opus while the ledger recorded Sonnet. Current prep construction does not supply these overrides, so the ordinary tested path is metered; the wrapper itself is not the claimed fail-closed boundary. **Fix:** canonicalize the final Converse request before reservation, or reject model/config/raw-block/cache overrides and enforce a single priced model and bounded output configuration. Explicitly reject prompt-cache blocks/control unless their write/read rates are accounted, since caching is described as disabled but not prohibited. Test nested overrides, bound copies and async calls without network access.

4. **P2 — The public prep endpoint can spend the host's remaining budget without host authorization.** `server/app/main.py:86-98` allows any caller to POST a known hero with force=true. The building existence check at `:90` authorizes an ID, not a caller; existing host actions require the PIN (`server/app/commands.py:31-33`, `:112-115`). A phone user or public-tunnel visitor can force research, consume the remaining capped allowance, and replace published personas. **Reproduced with mocked prep:** an unauthenticated POST with no PIN returned 200 and invoked forced prep despite HOST_PIN being configured. **Fix:** protect paid/forced prep with host authorization or keep it CLI/local-only, preserving ordinary read-only building/persona endpoints. Verify unauthorized requests never construct/invoke the model.

For Esperson, an allowed grounded intro could be “I was completed in 1941. Darling, make your next act worth my time.” The first sentence must resolve to the construction-completion fact; the second is clearly character fiction, not fabricated history. Use only supported physical/history clauses, reject unapproved factual numbers/entities, and add a small editorial rubric/eval for distinct era voice, humor and investor stakes. This can start with composable deterministic templates and reviewed fictional variants without another paid grounding call.
