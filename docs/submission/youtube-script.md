# Lights On — submission video

**Goal:** show a complete negotiation and the shared light-up in a video under two minutes. Use the [judge playbook](demo-script.md) for exact phone controls, pitches, revision options and recovery. This recording guide uses the same flow.

## Before recording

1. Run the prepared kit/live demo on the intended machine. Use the current launcher URLs for `/screen`, `/play` and `/admin`; saved tunnel links can expire.
2. Reset the room, join two players, and start audio before recording. Keep the host PIN, admin panel, terminals and credentials out of the capture.
3. Capture `/screen` at 1920 × 1080. If possible, add a small real phone-camera view or a brief phone insert so judges can see the input and charging. Keep it clear of the building, subtitles and evidence.
4. Use the board-game cafe and coworking pitches in the judge playbook. Prepare text in advance. Adapt the revision to the actual challenge; do not replace the model's reply with a scripted reply.
5. Make a short audio test and play it back. Confirm the recording contains both the presenter and building voice. Avoid capturing the same speaker audio twice through system audio and a microphone.
6. Keep the full original take. Each live attempt consumes Bedrock budget; fixture practice is the free way to rehearse controls.

## Record by phase; edit to this target

These are **editing allocations**, not promises about live server timing. Live generation may make the raw take longer than two minutes. Trim setup and dead time transparently; preserve the order and the meaning of the interaction.

| Video target | Show | Voiceover / presenter |
| --- | --- | --- |
| **0:00–0:10** | Skyline, QR, joined phones. Brief aim gesture, then **Wake building Esperson**. | “What if the building judged your idea? Lights On is Shark Tank, but the investor is a dark skyscraper.” |
| **0:10–0:20** | Camera dive, aerial and Matterport introduction. | “Real Houston office data becomes the game board.” Then let the building speak. |
| **0:20–0:36** | The two actual submitted pitches. Include a phone input shot if available. | “We pitch a board-game cafe. Our opponent proposes a coworking hub. The building gets to push back.” |
| **0:36–0:56** | Actual challenge and cited evidence. Keep the essential counteroffer readable and audible. | Let the building speak. Afterward: “Its challenge comes from its own dossier.” |
| **0:56–1:12** | Actual revision typed/pasted and **Send revision**. | “It asked us about [actual request]. We changed [actual part of the proposal] to answer.” |
| **1:12–1:28** | Actual winner, reason and scorecard. | Let the verdict speak. If there is room afterward: “The model proposes; the server validates the result.” |
| **1:28–1:40** | Both phones tapping, energy reaching 100%, winning floors lighting up. | “Even if your pitch lost, you help bring it to life.” Then leave room for the sound and reveal. |
| **1:40–1:50** | Short recorded-research panel shot, if readable. | “Esperson's research was prepared with deepagents on Bedrock. Live negotiation uses its dossier, with server-side validation.” |
| **1:50–1:58** | Return to a shot of the actual light-up / concept card from this round. | “You compete for the pitch, but everyone shares the skyline. Real data. Your ideas. Lights On.” |

If the video is too long, remove the trace segment before cutting the counteroffer, revision or light-up. The product story matters more than showing every integration.

## Editing rules

- Do not manufacture a winner, stitch different rounds into an apparent single outcome, replace a response, or invent a citation.
- If you shorten a generation wait, use a visible cut and a small “wait shortened” label. Do not imply edited timing is a latency measurement.
- If using fixture/fallback dialogue, label it. If replaying prep, keep “recorded research” visible.
- Keep the city simulation and game-concept labels readable. Do not claim a building was actually renovated.
- Show the input that led to the response. Do not use the prewritten revision if it doesn't answer the actual counteroffer.
- If audio needs repair, retain the building's actual words as subtitles. Do not imply a rerecorded presenter voice is the model's voice.
